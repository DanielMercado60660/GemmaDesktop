# Security and operational limits

The host controls permissions. Prompts, repository instructions, skills, MCP descriptions, and web content cannot grant authority. Versioned capability profiles are frozen at run admission and checked at execution, including the inner server/tool identity of generic MCP calls. Read-only mode removes mutating tools and is checked again by the executor. Each consequential operation requires a host approval tied to its exact detached arguments. Decisions are persisted before delivery and cannot be answered twice. Recovery cannot silently acquire a newer profile or reset remaining budgets and deadlines.

File access uses a selected root and pinned directory descriptors. Absolute/parent traversal, symlink components, credential directories, `.git` writes, and agent-policy files are protected. Reads and edits accept regular bounded UTF-8 files. Edits use the full original hash and preserve recorded before/after contents. There is no portable atomic compare-and-swap against arbitrary external editors; changes detected before replacement fail with a conflict. Root confinement does not by itself isolate processes.

The restricted executor uses a macOS sandbox. It denies network and child process creation, clears inherited credentials/environment, confines writes to the workspace/private temporary directory, and bounds output/time. Failure to apply the sandbox is an error. Git inspection uses fixed arguments and disables hooks, external diff/textconv, fsmonitor, and interactive prompts.

The explicit Docker profile supports subprocesses in a digest-pinned offline Linux image. Guests receive filtered private project copies, private caches and temporary storage; they do not receive the original project mount, host home, credentials, app database or Docker socket. Owned containers and descendants stop before result collection. Read-only commands have read-only source mounts. Source publication validates the original inputs and journals bounded byte-preserving changes. Ordinary nonzero exits may publish; timeout, cancellation and uncertain execution discard unpublished changes. A failed cleanup or unfinished publication blocks new admission until reconciliation. Per-file journal recovery is not a global filesystem transaction against arbitrary external editors. See the [complete executor contract](../internal/execution/README.md).

Public dependency setup is a separate visible operation with bounded integrity-locked downloads and offline installation. No guest receives network access. The 2 GiB/100,000-entry retained-state monitor permits interval overshoot and is not a hard disk quota. Reported logical file bytes exclude Docker image/VM allocation. The application never starts Docker, downloads images or installs Apple's container runtime implicitly.

The interactive terminal is an explicit user-account shell. Its approval explains that it can access user files and networking. It is not exposed as an agent tool. Shell startup files and inherited secret variables are not loaded.

Ollama uses a loopback-only origin with proxy inheritance and redirects disabled. Model metadata is inspected for remote targets before inference. The app does not change an unrelated shared Ollama configuration or terminate a shared daemon. The validation daemon was started with cloud disabled.

Chat text is limited to 512 KiB of serialized messages, thinking, tools, options and JSON overhead before HTTP dispatch; image payloads are excluded and require separate modality accounting. This is a resource bound, not a token estimate. On Ollama 0.32.3 MLX, requested `num_ctx` is a soft performance setting and the runtime report reflects that setting; the runner enforces the model's architectural maximum separately. Explicit `truncate:false` and `shift:false` request preservation, but do not turn the soft setting into a hard limit. ADK compaction remains the host's context-management strategy. Metadata has 30-second deadlines, load/unload a five-minute total cap, and chat uses the run deadline.

MCP connections are bound to canonical workspace roots and frozen configuration. Input and optional output schemas share a bounded approval hash; arguments are validated before approval, and successful structured results are checked against the declared output schema. Error results may omit the success-shaped structured value. Unsupported external schema references are rejected without fetching them. Invalid output is reported as an uncertain operation outcome because the server may already have performed a side effect; it is not automatically retried.

The official SDK's public sending middleware clears the local TTL on tool-list results, so discovery before and after approval does not reuse the SDK's cached list. This verifies the schemas advertised in those responses; it cannot prove that a remote server or intermediary is truthful/current, or prevent a change after the last check. Tests cover positive-TTL, unnotified input/output schema drift while approval is pending. Tool calls are independently approved; protocol roots are not treated as isolation. Stdio servers retain the restricted executor even when a coding profile uses Docker.

HTTP OAuth uses a native-browser authorization-code flow with PKCE, state/issuer validation, explicitly bounded resource/authorization/token endpoints and Keychain-backed credentials. SDK metadata discovery is preferred; the explicit-endpoint fallback requires absent supported metadata and never accepts invalid or mismatched metadata. Credentials stay out of model context and execution guests. Refresh never blindly replays an uncertain action. Sign-out clears local credentials without provider-side revocation. Controlled-provider and Keychain tests do not establish external-provider interoperability. Do not place credentials in command arguments, ordinary config or URLs.

Browser tasks use a fresh Chrome profile without the Wails bridge. An origin proxy permits only the approved origin, blocks unapproved redirects/resources, and validates destinations. Browser clicks and text entry are separately approved, and credential fields are unavailable. The ordinary application never renders arbitrary active HTML or web content in its privileged origin.

Database recovery expires outstanding approvals, marks unfinished runs/experiments interrupted, and labels started tool intents with no outcome as uncertain. It does not replay commands, writes, MCP actions, or browser clicks. Only explicit workflow approval checkpoints have supported resumption. Quitting the application stops its owned work; there is no guarantee of execution after process exit.

Full skill bundles retain immutable bytes, hashes and provenance. Binary resources use artifact handling; approved materialization does not execute scripts. Local specialist delegation is read-only, shares parent budgets/deadline and cannot recursively delegate. Durable plan completion is a claim, not a permission or independent grade.

The experimental evaluator cannot change these policies. Coding trials use isolated inputs and the same frozen model/runtime/executor conditions. Solver-controlled code executes only in the guest and is never imported into the host grader. Hidden assertions and expected answers are excluded from solver, proposal and lesson packets; exposure retires a task from the unseen pool. Codex proposals are declarative and hash-bound. Graders, security policy, model weights and executable plugins are outside their editable surface. Failed and incomplete trials remain in the denominator. Promotion requires integrity, held-out success, resource-efficiency and independent-review gates; rollback is recorded against the named target only.
