# ADK integration follow-up audit — 27 October 2026

Scope: the implemented Gemma Desktop runtime against product specification v1 sections 4, 6, 8 and 10, and the actual pinned ADK Go source. This is an implementation audit, not evidence of another successful real-model task. The realistic coding candidate is being evaluated separately.

Pin: `google.golang.org/adk/v2 v2.6.0`, upstream commit `5226417e7591bb75d680047b01578e0fa6078f09`, released 13 October 2026. The local module-cache origin metadata and `go.sum` identify the source. Selected files were also checked through the GitHub connector at that exact commit. Python documentation and newer main-branch behavior are not treated as released Go capabilities.

## Coverage and boundaries

| Requirement | Actual implementation | Assessment |
|---|---|---|
| Autonomous multi-turn execution | `engine.Agent` constructs an ADK `llmagent`; `runner.Run` owns the tool/model loop. Native Ollama adapter implements `model.LLM`. | Real framework integration, not a parallel handwritten LLM loop. |
| Task planning | Default instructions ask for a brief plan. There is no structured plan entity/tool with persisted step status. | Prompt-level planning exists; a tracked planning surface remains a product-depth gap. |
| Delegation | Saved workflow agent nodes resolve frozen agent instructions/model/step limits; dynamic fan-out runs actual ADK child nodes. | Configured local cooperation exists. Ordinary chat agents cannot choose or spawn approved subagents themselves. |
| Graphs | ADK DAG edges, string conditions, unconditional joins, bounded runtime fan-out, approval nodes. | A deliberate supported subset: not arbitrary model-authored graph code or cyclic graphs. |
| Human approval recovery | Immutable definition hash, frozen resolved-agent snapshot, completed-node outputs, cumulative model/tool/output counters, durable pending interrupts. | Supported approval boundaries are recoverable; arbitrary in-flight tools are not replayed. |
| Context | Full completed ADK event/state snapshots; new tail-only compaction with retained recent events and append-only summary actions. | Automated qualification passes; long-session live quality remains separate evidence. |
| Completion | Model final prose plus tool/artifact journal and execution status. | An execution ending successfully is not an independent correctness verdict; completion needs evidence receipts. |

The Go release's natural-language planning request/response processors are explicitly TODO implementations. A Python `Planner` recipe cannot be imported by analogy. A structured plan can instead be a bounded ADK function tool that records app-owned state/events; it must not become another scheduler or grant execution rights. See [released planning processors](https://github.com/google/adk-go/blob/5226417e7591bb75d680047b01578e0fa6078f09/internal/llminternal/other_processors.go).

The release does provide `llmagent.Config.SubAgents`, delegation modes and automatic task/single-turn tools, plus `tool/agenttool`. Our normal chat agent currently configures none of these. If open-ended delegation is added, select only frozen allowlisted agents, inherit read-only restrictions, keep one shared budget and inference client, bound depth/child count, and emit parent/child identities. Agent tools create subordinate sessions; their availability alone does not establish durable child recovery. See [LLM agent modes](https://github.com/google/adk-go/blob/5226417e7591bb75d680047b01578e0fa6078f09/agent/llmagent/llmagent.go) and [agent-tool session creation](https://github.com/google/adk-go/blob/5226417e7591bb75d680047b01578e0fa6078f09/tool/agenttool/agent_tool.go).

## Correctness defects repaired during this audit

**Length-limited generations.** The adapter previously set `FinishReasonMaxTokens` for Ollama `done_reason=length`, while `RunAgent` treated the final event as normal completion. Upstream `Event.IsFinalResponse` does not inspect the finish reason. A nonempty answer, or apparently usable tool arguments, therefore did not prove a complete generation. The ordinary adapter now returns `ErrIncompleteResponse`, preserving text/usage in an explicitly incomplete result and streaming audit, without publishing a completed ADK model turn or executing any proposed tool calls. The incomplete turn is absent from the continuation snapshot. Summary generation separately returns MAX_TOKENS to ADK's summarizer, which rejects incomplete summaries. [Upstream final-response predicate](https://github.com/google/adk-go/blob/5226417e7591bb75d680047b01578e0fa6078f09/session/session.go#L214)

**Dynamic fan-out failure cancellation.** The original app fan-out waited for every worker before returning the first error. ADK's static scheduler cannot cancel the enclosing node's other children until that error returns, and its dynamic scheduler reports child failure to the caller rather than automatically aborting every sibling. The app now cancels a shared group at first failure, prevents queued items from starting, explicitly bridges group cancellation into active child runs, waits for them to finish, and preserves the original failure. The bridge matters because `RunNode` uses its stored sub-scheduler parent context. Already emitted tool receipts remain in the app journal; cancellation cannot undo effects. [RunNode contract](https://github.com/google/adk-go/blob/5226417e7591bb75d680047b01578e0fa6078f09/workflow/run_node.go#L129) · [dynamic scheduler](https://github.com/google/adk-go/blob/5226417e7591bb75d680047b01578e0fa6078f09/workflow/dynamic_scheduler.go)

**Tool evidence presentation.** Built-in tools supplied both structured data and the same JSON document as text. The model then saw another JSON serialization of that wrapper. First, semantically duplicate text is omitted. Second, the model-facing Ollama adapter renders successful `read_file` results as metadata plus literal untrusted source, and process/Git results as metadata plus literal stdout/stderr. This fixes representation without fuzzy editing, automatic unescaping or authority changes. ADK's structured function response remains unchanged for snapshots and audit. Exact multiline source, literal backslashes, quotes, Unicode, hashes, error status and process diagnostics are covered through JSON transport tests. This change was motivated by the preserved live baseline's repeated exact-edit failures, not by relaxing its test oracle.

## Compaction policy and limitations

`Request.ContextPolicy` enables ADK `runner.Config.Compaction`. The application now explicitly enables it for new runs; engine callers with nil policy retain the prior behavior.

- Tail-retention only, default threshold 60% of requested context (19,660 tokens for 32,768), default eight retained events. ADK extends cuts to preserve complete function-call/result pairs and the current user turn.
- Dedicated summary model: same local model/client, no tools or skills, thinking off, temperature zero, 45-second timeout, at most four summary calls per turn. Every call and output byte counts against the shared execution budget.
- Summary output bound is `min(1536, max(256, contextSize/4))` tokens. ADK deliberately drops inherited `MaxOutputTokens`, so this bound is enforced at the dedicated adapter rather than assumed from `GenerateContentConfig`.
- Summary transcript is capped at `contextSize` characters; each tool item at 4,096 characters. The summary prompt preserves task constraints, identifiers, decisions, observed evidence and unresolved work; it explicitly treats source/tool text as untrusted.
- Summary actions append to the session; original events remain in snapshots. A session-service observer publishes the otherwise invisible compaction commit to the app journal. UI events distinguish starting, committed, and failed summaries.
- An incomplete/failed summary leaves the raw history intact. ADK degrades to an uncompacted prompt; the subsequent main request still obeys budgets/cancellation.

This is lossy context management, not unlimited memory or a mathematically exact context-fit guarantee. The threshold uses model usage and upstream estimation. Large current tool turns can still exceed context; summary transcript truncation can lose old details. The original audit is retained, but the app does not yet provide an agent retrieval tool over archived conversation evidence. Snapshot storage is also not compacted: the engine rejects imports above 64 MiB. Archival/retrieval and exact durable task constraints should be separate work before claims about indefinite sessions. [Compaction contract](https://github.com/google/adk-go/blob/5226417e7591bb75d680047b01578e0fa6078f09/session/compaction/compaction.go) · [summary config filtering](https://github.com/google/adk-go/blob/5226417e7591bb75d680047b01578e0fa6078f09/session/compaction/llm_summarizer.go#L436)

## Persistence, recovery and completion

The app's single SQLite store owns durable intents, approvals, tool results, artifacts, configuration and snapshots. It does not use ADK's optional SQL service. Each run restores an in-memory ADK session, then exports completed events and state. Display events have bounded payloads; full tool results and completed snapshots live in separate authoritative records. A large display event is not itself a complete reconstruction source.

`ReconstructRunState` is an interrupt-history reconstruction API, not a general process checkpoint. The current immutable DAG wrapper restores verified completed outputs to work around released join-resume gaps. Tests cover a completed predecessor, separate replies to parallel approvals, stale replies and rejected approvals. The application consumes the old pending checkpoint before dispatching successors; a crash after that boundary cannot re-enable it. Started external effects without receipts become uncertain. Nested LLM child sessions are independently run and their completed node outputs retained; mid-child crash recovery is deliberately unsupported. [Released reconstruction](https://github.com/google/adk-go/blob/5226417e7591bb75d680047b01578e0fa6078f09/workflow/persistence.go)

Remaining completion work is app-owned: attach observed command exit codes, affected paths and receipt IDs to final output, label absent verification, and distinguish the model's explanation from independent evidence. A command named “test” is not automatically a trusted correctness oracle; evidence should state exactly what ran. The realistic fixture's immutable public tests and separately held acceptance suite provide stronger evidence for that experiment only. The parent integration lane is implementing the receipt.

Execution budgets preserve model calls, tool calls and output bytes across workflow approval recovery. Wall-clock deadlines are applied per execution attempt; elapsed historical wait time is not a cumulative persisted budget. Document that distinction if exposing a total-runtime setting.

## Verification and explicit exclusions

After the fixes above, `go test -race ./internal/engine ./internal/inference ./internal/workflow -count=1 -timeout=60s` passes. New tests cover: complete pair retention even with a one-event tail, current-turn preservation, durable summary restore, shared summary budget, incomplete summary rejection, cancellation, length-limited generations with and without tool proposals, exact literal source transport with unchanged structured snapshots, process error presentation, and fan-out failure with four active workers, three cancelled workers and twelve never started. These are local fixture tests, not model-quality benchmarks. Existing app integration tests cover durable approvals, consumed checkpoint non-replay, read-only enforcement, cancellation and shutdown.

Required next acceptance: the real multi-file SQLite/CSV task with protected original tests, new regression tests, independent acceptance, exact read-only test command, Git review and action-free continuation. Preserve failed attempts and report causal changes between attempts.

Deliberately excluded donor features include remote A2A federation, arbitrary autonomous subagent creation, distributed scheduling, transparent replay of uncertain effects, Python-only planning APIs, cyclic/unbounded graphs, automatic harness optimization, skill script execution and unrestricted subprocess trees. None is necessary to use ADK correctly. The specification's local configurable workflows are implemented; tracked planning, optional model-selected delegation and evidence-backed completion need precise capability labels rather than claims that every donor application's feature has been reproduced.
