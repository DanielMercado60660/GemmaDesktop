# Reference audit — 27 October 2026

This audit compares the [original product specification](../reference/product-specification-v1.md), the implementation working tree based on `93ff161798d6048815a9e6429189bf9184e00a56`, and primary source material from the six requested projects. It identifies useful workflow contracts, not a requirement to reproduce every donor feature or replace ADK-Go. No donor code was copied and no inference or model download was performed for this audit.

The working tree is changing during qualification. **Implemented** means present in inspected source; it does not mean a newly packaged native build has passed acceptance. **Must-fix** identifies a correctness, evidence, or claim gap before extending the product. **Intentional-limit** describes an explicit current boundary. **Optional** identifies useful work beyond that boundary. The release report must record the final test results separately.

### Additional boundary checks from the integration pass

**Implemented — fresh MCP schemas and uncertain outcomes.** [MCP dispatch](../../internal/mcp/manager.go) now disables the SDK's local tool-list TTL reuse, discovers before and after approval, hashes both input and output schemas, validates input, and rejects intervening schema/connection changes. Successful structured results are checked against the approved output schema; error results need not match a success schema. Transport failure after dispatch, oversized results, and invalid success output report an unknown outcome, because the remote operation may already have completed. [Schema fixtures](../../internal/mcp/schema_test.go) exercise unnotified input/output drift under advertised TTL and invalid structured results. These checks pin advertised schemas at the checks; they cannot freeze remote server behavior after the final response. OAuth and resumable elicitation remain explicit limits.

[Receipt/recovery handling](../../internal/app/receipt.go) carries uncertainty forward, and [the completion fixture](../../internal/app/receipt_test.go) ensures an unknown MCP outcome cannot become verified completion even when model prose claims success. Do not automatically retry a write to recover a missing response. This implements the existing security research's contract rather than adding a new authority for a model or donor runtime.

**Implemented — bounded projections with explicit full-detail reads.** [ToolSummary](../../internal/store/run_records.go) aggregates whole-run failure/unresolved counts in one SQLite snapshot while returning bounded recent records (at most 200 records and 256 KiB), omitting raw file before/after bodies and bounding arguments/errors/diagnostic tails. Recovery text has a 16 KiB total bound and retains the aggregate unresolved count even when older details are omitted. [Store fixtures](../../internal/store/run_records_test.go) and [receipt fixtures](../../internal/app/receipt_test.go) cover bounds, omission flags, and retained uncertainty. This avoids reloading large source snapshots merely to construct a compact receipt.

Artifact polling now returns metadata only; `artifact.get {id}` retrieves full content on explicit selection. The frontend displays loading/error/retry states, rejects stale-selection responses, and distinguishes missing content from a real empty-file diff. Native QA selected the real stored `repository.py` artifact from the metadata-only list and rendered its Monaco diff through the lazy fetch. [Native record](../evidence/native-workflow-followup.json), [screenshot](../evidence/screenshots/native-lazy-artifact.png). Full durable artifact records are unchanged. This is bounded presentation/recovery work, not a claim that every table or the entire application state has a global storage quota.

## What each reference contributes

### Gemini CLI: durable work, explicit plans, and separate kinds of recovery

Gemini's session documentation includes prompts, responses, tool inputs/results, and usage in saved history. Its optional checkpoint feature couples a shadow Git snapshot with conversation state and the pending tool proposal. Its planning tools establish a distinct phase with host-enforced restrictions and explicit plan approval. These are different contracts: restoring context, reverting files, and executing an approved operation must not be conflated. [Session management](https://github.com/google-gemini/gemini-cli/blob/363a13119a57354f469732577518b9d6b319d1d6/docs/cli/session-management.md), [checkpointing](https://github.com/google-gemini/gemini-cli/blob/363a13119a57354f469732577518b9d6b319d1d6/docs/cli/checkpointing.md), [planning tools](https://github.com/google-gemini/gemini-cli/blob/363a13119a57354f469732577518b9d6b319d1d6/docs/tools/planning.md).

**Implemented:** Gemma has immutable run requests, persisted ADK snapshots, durable tool intents/outcomes, host-owned approval/read-only modes, selected-file checkpoints, and resumable native workflow approval nodes. **Intentional-limit:** those checkpoints are bounded text before-images, not whole-repository rewind or generic crash replay. The current policy correctly rejects uncertain external-effect replay.

**Optional:** a persisted task list and reviewable plan artifact would make substantial coding tasks easier to follow than prose alone. The donor's [todo contract](https://github.com/google-gemini/gemini-cli/blob/363a13119a57354f469732577518b9d6b319d1d6/docs/tools/todos.md) is a useful model for pending/in-progress/completed work, but Gemma should store it in its existing event system rather than add another runtime. Project instruction discovery is also useful: Gemini documents hierarchical project rules and an active-context inspection surface. Gemma currently relies on agent instructions, explicit attachments, imported skills, and reads initiated by the agent; it does not advertise equivalent automatic hierarchical discovery. If added, show exactly which files contributed guidance and keep them below user/host authority. [Project context](https://github.com/google-gemini/gemini-cli/blob/363a13119a57354f469732577518b9d6b319d1d6/docs/cli/tutorials/memory-management.md).

### Qwen Code: ownership and freshness at asynchronous boundaries

Qwen's navigation design binds prompts to their owner and a generation, rechecking ownership around asynchronous admission and restoration. Its source tracks session epochs, client ownership, and selection generations. That directly motivated the composer repair above; “the selected chat” is not a durable request address. [Navigation contract](https://github.com/QwenLM/qwen-code/blob/32f6713ce6394b48dc384d301ee761fb9a1b5b80/docs/design/2026-08-11-prompt-safe-session-navigation.md), [navigation store](https://github.com/QwenLM/qwen-code/blob/32f6713ce6394b48dc384d301ee761fb9a1b5b80/packages/web-shell/client/daemon/session/turn-navigation-store.ts).

Its edit implementation checks prior reads, rechecks freshness after reading and before writing, preserves encoding/line endings, and provides concrete mismatch recovery. Gemma already uses expected hashes, exact edits, bounded before-images, and frontend draft preservation. Do not describe hash checks plus rename as universal atomic compare-and-swap against unrelated editors. **Intentional-limit:** supported text files only; arbitrary encoding/binary editing is not qualified. [Edit implementation](https://github.com/QwenLM/qwen-code/blob/32f6713ce6394b48dc384d301ee761fb9a1b5b80/packages/core/src/tools/edit.ts).

**Optional:** a context inspection panel can distinguish unknown, measured, estimated, and historical readings. Qwen explicitly refuses to invent absent usage and treats a compression result separately from a later refresh. Gemma's runtime panel currently shows real measured throughput and capacity; a context meter must meet the same evidence standard before addition. [Context overview](https://github.com/QwenLM/qwen-code/blob/32f6713ce6394b48dc384d301ee761fb9a1b5b80/docs/design/2026-09-12-web-shell-context-compaction.md).

### OpenWork: session identity and honest product boundaries

OpenWork documents misrouted messages caused by focus-bound composer controls, then separates by-ID session actions from explicit UI navigation. Its security architecture also distinguishes local harness permission checks from OS confinement. These are useful contracts independent of its current OpenCode/cloud architecture. [Session control](https://github.com/different-ai/openwork/blob/fa29840a71b371951df3b0cd2bee3fb3fb48539d/docs/features/headless-session-control.md), [security architecture](https://github.com/different-ai/openwork/blob/fa29840a71b371951df3b0cd2bee3fb3fb48539d/docs/security/openwork-architecture.md).

**Implemented:** Gemma calls runs by stable session IDs and has a separate constrained executor; the composer correction closes a local ownership gap. **Intentional-limit:** one active mutating run per workspace, no mid-turn prompt queue, no autonomous control of the user's foreground UI, and no shared organization/cloud control plane. A rejected second run must remain visible and preserve its draft.

**Intentional-limit; delivery wording reconciled:** the delivery table now explicitly states that there is no per-agent tool/skill allowlist editor. Current configurable fields are instructions, model, step budget, read-only/approval mode, explicit thinking preference, response token limit, and temperature; imported skill metadata is made available to runs. Fine-grained capability profiles are optional additional work. Before copying any future donor implementation, inspect its exact file license: OpenWork's current README describes separate terms under `ee/`. [Licensing](https://github.com/different-ai/openwork/blob/fa29840a71b371951df3b0cd2bee3fb3fb48539d/README.md#licensing).

### OpenWorker: execute real workflows without overstating isolation

OpenWorker separates its agent/credentials/connectors from its sandboxed tool runner. Its macOS profile explicitly allows process creation and confines networking to a broker when configured; the source is more precise evidence than the product slogan. Delegated approval guidance states that the original worker operation is reviewed and a lead agent's recommendation does not confer permission. [macOS design](https://github.com/andrewyng/openworker/blob/59151e3b306d9edc2b22e6e2bb4443316f563f47/docs/macos-sandbox.md), [profile source](https://github.com/andrewyng/openworker/blob/59151e3b306d9edc2b22e6e2bb4443316f563f47/coworker/sandbox/providers/seatbelt_profile.py), [approval guidance](https://github.com/andrewyng/openworker/blob/59151e3b306d9edc2b22e6e2bb4443316f563f47/docs/approval-guidance.md).

**Implemented:** Gemma confines approved agent commands, strips ambient credentials, denies networking and process-fork, keeps exact tool approvals outside model control, and separates the explicitly approved user terminal from agent tools. **Intentional-limit:** single-process Python/SQLite tasks are not evidence that npm, compiler drivers, package installation, local web servers, or subprocess-heavy builds work. Current working-directory and read-only verification options do not change that boundary.

**Optional:** a separately qualified process-tree executor with private caches and controlled networking. Before enabling it, test descendant cancellation, inherited confinement, credential absence, and direct/proxy-bypass egress. Do not copy a more permissive profile merely to make a build pass. The earlier [security research](security-and-persistence.md) already sets these conditions.

### Harness²: comparison evidence before automated improvement

Harness² distinguishes task-level harness refinement from accumulated improvement knowledge. Its experiment guide requires consistent task/model/executor/judge/network conditions, records dataset revisions, separates failed evaluation from a zero score, and explains that the seed controls task ordering rather than model sampling. It also discloses unrestricted executor networking and accessible public rubrics. [Overview](https://github.com/google-research/harness2/blob/1cfe254e8d25b15f37048c3730134686abe60335/README.md), [experiment contract](https://github.com/google-research/harness2/blob/1cfe254e8d25b15f37048c3730134686abe60335/docs/EXPERIMENTS.md).

**Implemented:** Gemma's [evaluation service](../../internal/app/evaluation.go) freezes bounded text inputs and both configurations, records an input digest, and retains answers, usage, timing, and tool evidence. **Intentional-limit:** it is a read-only comparator, not an objective correctness judge, coding benchmark, or autonomous optimizer. Different step budgets, models, thinking preferences, response token limits, or temperatures in selected configurations must be treated as changed experimental variables.

**Must-fix acceptance before promoting a “better harness”:** use independent acceptance checks or a documented rubric, hold out tasks, preserve failed attempts, and report exact model/configuration/input versions. **Optional:** candidate proposal, repeated trials, explicit promotion/rollback, and longer-term lesson libraries. None should grant a candidate new permissions to improve its score.

### A2A Go: a future remote boundary, not a local orchestration dependency

The inspected README targets A2A protocol v1.0 and explicitly distinguishes SDK and protocol versions. Its task-store API defines optimistic concurrency/version rejection; cancellation tests exercise competing execution and cancellation while preserving the cancelled task state. [README](https://github.com/a2aproject/a2a-go/blob/2692308d0926f05fa8e7892e2dacb099848200fe/README.md), [task-store contract](https://github.com/a2aproject/a2a-go/blob/2692308d0926f05fa8e7892e2dacb099848200fe/a2asrv/taskstore/api.go), [cancellation tests](https://github.com/a2aproject/a2a-go/blob/2692308d0926f05fa8e7892e2dacb099848200fe/e2e/cancellation_test.go).

**Intentional-limit:** local ADK agents/workflows do not expose an A2A server. This is not missing local delegation. **Optional:** remote-agent access needs explicit endpoint/data-sharing grants, authenticated ownership, supported protocol-version negotiation, bounded streaming/artifact handling, and cancellation receipts. A disconnect does not prove a remote operation stopped. Do not automatically upgrade ADK's transitive protocol dependencies to this inspected head.

## Additional product boundaries confirmed in the final pass

- **Workflow authoring:** the engine supports dynamic fan-out. The destructive editor round-trip defect is fixed in [workflowEditor.ts](../../frontend/src/lib/workflowEditor.ts): existing item arrays are preserved exactly, and [the editor](../../frontend/src/Workflows.tsx) exposes agent selection and JSON arrays of up to sixteen strings. Blank/empty arrays retain the backend's runtime-input behavior. Five serialization regressions and [native save/reopen checks](../evidence/native-final-ui-fixtures.json) verify multiline, empty, and Unicode strings, plus invalid-item rejection; new node IDs satisfy backend validation. This is authoring/persistence evidence, not an executed model fan-out. Native typing exposed smart-quote substitution; the final package disables spellcheck/autocorrection/capitalization on the JSON textarea, with TypeScript validation. Cycles and conditional joins remain explicitly rejected by backend validation.
- **Model-facing Git review:** the combined HEAD/staged/unstaged/new-file Changes pane is broader than `git_diff`, which exposes tracked unstaged or staged diffs separately. The model must read new files explicitly; `git_diff` alone does not review generated untracked regression tests.
- **Attachment baseline:** chat attachments currently read bounded workspace text (128 KiB) into the prompt. They do not ingest images, audio, or video. Video retrieval needs a separate bounded decoder/indexer and a qualified image-capable answer path; transcript-only retrieval does not establish frame understanding. See [the video design](video-rag-design.md).
- **Memory guidance:** the model panel measures total physical capacity and compares model artifact bytes against it. It does not measure current available unified memory or memory pressure. Those measurements and shared admission control remain prerequisites to qualifying concurrent media indexing and inference.
