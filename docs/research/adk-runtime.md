# ADK Go runtime research

Research date: October 26, 2026. The recommended architecture keeps ADK responsible for agent and graph execution, with Gemma Desktop responsible for authorization, durable application records, model admission, and external side effects. ADK Go v2 already supplies substantially more of the requested workflow machinery than a minimal agent loop, but its released version has recovery and cancellation gaps that must be tested before selecting the build pin.

## Version baseline

The newest v2 release found is **v2.6.0**, published October 13, 2026, at commit `5226417e7591bb75d680047b01578e0fa6078f09`. Its module is `google.golang.org/adk/v2` and its minimum Go directive is **1.26.6**. The newer release date of v1.9.0 belongs to the maintained v1 line; selecting the first GitHub release or a generic latest-release endpoint can select the wrong major. The current main snapshot inspected is `219c13059ecf654b7318d5927a607779711943e0`, October 26, with Go **1.26.10**. [Releases](https://github.com/google/adk-go/releases) · [v2.6.0 module](https://github.com/google/adk-go/blob/v2.6.0/go.mod) · [main snapshot](https://github.com/google/adk-go/commit/219c13059ecf654b7318d5927a607779711943e0)

Use v2.6.0 as the reproducible comparison baseline, not an automatic final dependency choice. There are 44 commits between it and the inspected main, including completed-predecessor recovery for joins, loop cancellation, timeout propagation, and invocation model-call budgets. Run the regression cases below against the release and an explicitly pinned candidate containing the needed fixes. Prefer a subsequent tested release; if unavailable, record a reviewed commit pin and its compatibility evidence. Do not silently follow main. [Release-to-main comparison](https://github.com/google/adk-go/compare/v2.6.0...219c13059ecf654b7318d5927a607779711943e0)

## Capability and ownership map

| Requirement | Confirmed Go implementation in v2.6.0 | Gemma Desktop responsibility |
| --- | --- | --- |
| Model execution | `model.LLM`, `llmagent`, `runner` and streaming iterators | Ollama transport adapter, capability negotiation, metrics and limits |
| Agent delegation | Subagents, chat/task/single-turn modes, agent tools | Immutable per-run configurations, bounded depth, workspace isolation |
| Sequential and parallel work | Workflow agents plus graph nodes and edges | Compile validated saved definitions into ADK nodes |
| Conditional and dynamic graphs | Routes, `DynamicNode`, `RunNode`, `JoinNode`, list workers | Reject unsupported graph shapes; bound dynamic dispatch |
| Human input and tool confirmation | `RequestedInput`, interrupt IDs, `Resume`, function-tool confirmation | Durable authorization decisions bound to exact operations |
| Sessions | `session.Service`; memory and GORM database implementations | Versioned app migrations and storage conformance |
| Artifacts | Versioned `artifact.Service`; memory and GCS implementations | Durable local file-backed implementation and metadata |
| Context compaction | Sliding window and rolling tail retention | Context budget policy, critical facts in state, storage redaction |
| Skills | `skilltoolset` with filesystem sources | Trusted installation, safe filesystem implementation, script permission checks |
| Cancellation and budgets | Contexts, node timeouts, optional retries/concurrency | Aggregate tool/model/time/output limits across all nested work |
| Remote agents | A2A adapters, including `agent/remoteagent/v2` | Optional network boundary; unnecessary for local delegation |

These are Go source findings, not assumptions based on Python feature tables. The [v2 migration notes](https://github.com/google/adk-go/blob/v2.6.0/README-v2.md) also matter: `session.NewEvent` now takes a context, and tool/callback contexts are unified under `agent.Context`.

## Model integration

`model.LLM` requires `Name()` and `GenerateContent(ctx, request, stream)`, returning `iter.Seq2[*model.LLMResponse, error]`. ADK represents messages and tools using `google.golang.org/genai` types even with another provider. Partial text events are forwarded to the consumer; the final non-partial event is what the runner fully processes and persists. The adapter must accumulate a complete response, preserve tool-call identity, and distinguish text deltas from the final authoritative content. A tool must never run from incomplete streamed arguments. [Model contract](https://github.com/google/adk-go/blob/v2.6.0/model/llm.go) · [runner persistence](https://github.com/google/adk-go/blob/v2.6.0/runner/runner.go)

There is an existing `model/openaimodel` adapter with configurable BaseURL and Chat Completions support, but it is explicitly experimental and defaults to the Responses API. Its Chat Completions path reads text, refusals, and tool calls, not provider reasoning fields; `ThinkingConfig.IncludeThoughts` has no equivalent there. It also rejects unsupported generation fields such as TopK. Tool schemas are sent without strict validation. An empty API key inherits `OPENAI_API_KEY` and can forward it to a custom endpoint. If used for a probe, set the API, URL, HTTP client, and a non-secret non-empty local key explicitly. [Adapter behavior](https://github.com/google/adk-go/blob/v2.6.0/model/openaimodel/doc.go) · [configuration](https://github.com/google/adk-go/blob/v2.6.0/model/openaimodel/openaimodel.go)

The preferred production path is a small native Ollama-to-`model.LLM` adapter if the compatibility path cannot preserve the required thinking mode, Ollama options, timing, and multimodal fields. Keep model management separate from inference: discovery/pull/delete/load/unload do not belong inside `GenerateContent`. The existing adapter is a useful reference for correct final tool-call accumulation, not proof of Gemma/Ollama compatibility. Its image/file input support also has post-release changes. [Streaming translation](https://github.com/google/adk-go/blob/v2.6.0/model/openaimodel/internal/completions/stream.go) · [post-release media support](https://github.com/google/adk-go/commit/74faa9ab6bf58b47653ed275f4aa86a93e76280a)

Thinking preservation is a concrete adapter requirement: Ollama v0.40.11's Gemma 4 renderer includes assistant thinking after the most recent user message, including the continuation around tool results. Discarding it between a tool request and the next model call changes that continuation. Preserve the provider's structured fields in the adapter; keep them distinct from user-visible answer text and from earlier-turn context. [Gemma 4 renderer](https://github.com/ollama/ollama/blob/v0.40.11/model/renderers/gemma4.go#L66-L98) · [inference research](inference-models.md)

## Graph definitions and execution

Use a versioned, declarative application format containing node IDs, registered node types, schemas, routes, agent references, and limits. Compile it in Go into ADK nodes and edges. Do not evaluate user-supplied Go or let React schedule work. Keep display layout separate from execution semantics. ADK validates node inputs/outputs and graph structure, but the application needs additional rules for known unsupported combinations. [Workflow interface and constructor](https://github.com/google/adk-go/blob/v2.6.0/workflow/workflow.go)

Important constraints in the released code:

- **Conditional edges into `JoinNode` can silently skip work.** The source explicitly warns that validation accepts this configuration, and the join/downstream nodes may never run while the workflow reports success. Restrict joins to unconditional predecessors that are guaranteed to participate, or model the conditional fan-in through an explicitly tested alternative. [Join implementation](https://github.com/google/adk-go/blob/v2.6.0/workflow/join_node.go)
- **Graph concurrency limits do not cover dynamic `RunNode` children.** `WithMaxConcurrency` caps graph-scheduled nodes only. Put a shared semaphore around actual model/tool activity, not around a parent waiting for its children, which could deadlock. Bound delegation depth and total calls separately. [Concurrency option](https://github.com/google/adk-go/blob/v2.6.0/workflow/workflow.go)
- **Stable dynamic run IDs are not a durable side-effect guarantee.** `WithRunID` deduplicates within an activation; its documented contract warns completed children may execute again across a human-input pause. It also prohibits IDs containing `/` or `@`, purely numeric IDs, and a non-dynamic node awaiting itself. [Dynamic execution options](https://github.com/google/adk-go/blob/v2.6.0/workflow/run_node.go)
- **Peer context visibility is deliberate.** Dynamic children inherit their parent's branch unless sub-branch/isolation options are supplied. Use separate branches/scopes for independent workers, then aggregate explicit outputs. [Branch and isolation options](https://github.com/google/adk-go/blob/v2.6.0/workflow/run_node.go)
- **Retries need a side-effect policy.** Nil retry configuration means no retries; the provided default retries five times and excludes only input-validation errors. Do not apply it indiscriminately to shell commands, edits, network mutations, approvals, or user cancellations. [Node and retry configuration](https://github.com/google/adk-go/blob/v2.6.0/workflow/config.go)

## Human approval and recovery

Use ADK's interruption protocol to suspend agent/workflow execution, but enforce authorization again inside the application tool broker. `functiontool.Config` offers fixed and argument-dependent confirmation, while the handler receives an `agent.Context`. Validation and permission decisions should be shared by direct tools, MCP tools, workflow tool nodes, and skills so none becomes an alternate route around policy. [Function tools](https://github.com/google/adk-go/blob/v2.6.0/tool/functiontool/function.go)

Create a unique interrupt ID for each request. Store the exact tool name, canonical arguments, workspace, target/precondition hashes, grant scope, and decision in the application database. A changed command or file precondition requires revalidation. Do not accept a model-generated confirmation object as an authorization decision. ADK's human-input event is correlated through `adk_request_input` and FunctionResponse IDs. [Input requests](https://github.com/google/adk-go/blob/v2.6.0/workflow/request_input.go)

There are two resume modes. Handoff passes the response to successors; re-entry runs the asking node again. Duplicate re-entry responses can execute the node again, whereas a duplicate handoff can report `ErrNothingToResume`. Deduplicate UI submissions durably before invoking ADK. Concrete route conditions are not evaluated from a handoff response; an explicit decision node after the approval is clearer. [Resume implementation](https://github.com/google/adk-go/blob/v2.6.0/workflow/resume.go)

ADK's `ReconstructRunState` rebuilds paused runs from event history scoped by invocation ID. It returns no state when no interrupt history exists; it is not a general guarantee that any process crash can transparently resume arbitrary shell/tool work. The released constructor also contains an explicit warning that graph evolution is not fingerprint-checked and can corrupt resumption. Save an immutable workflow/agent/model/harness snapshot and its hash per run. Treat an operation interrupted between external execution and result persistence as **outcome unknown**, then inspect or reconcile it before retrying. [Reconstruction](https://github.com/google/adk-go/blob/v2.6.0/workflow/persistence.go) · [graph compatibility warning](https://github.com/google/adk-go/blob/v2.6.0/workflow/workflow.go)

The October 19 fix for restoring completed predecessors on join resume spans workflow, runner, agent-tool, and A2A tests. This is a high-priority dependency-selection gate, not a cosmetic patch. [Fix and regression coverage](https://github.com/google/adk-go/commit/d3ab7bfefffde86d2d2344d3c5acef574a3bf272)

## Persistence and observability

Use ADK's `session.Service` interface as the persistence seam. The bundled GORM service accepts an existing DB, uses transactions, and does not create tables until explicitly migrated. It intentionally ignores partial streaming events and strips temporary state. Its schema includes workflow outputs, routes, node information, requested input, branch/isolation identity, usage, and custom metadata. Choose either controlled migrations for these tables or a custom service with the upstream conformance suite; do not casually omit fields when designing an app event table. [Database service](https://github.com/google/adk-go/blob/v2.6.0/session/database/service.go) · [storage schema](https://github.com/google/adk-go/blob/v2.6.0/session/database/storage_session.go) · [service contract](https://github.com/google/adk-go/blob/v2.6.0/session/service.go)

**Do not inherit the SQLite version without checking it.** ADK's release and inspected main select `modernc.org/sqlite v1.46.1`, whose documented Darwin engine is SQLite **3.51.2**. SQLite documents a rare WAL reset corruption bug fixed in **3.51.3**, with backports 3.50.7 and 3.44.6. This matters when multiple connections can write/checkpoint the same database. Upgrade to a tested fixed engine with its matching `modernc.org/libc` dependency, and gate WAL startup on `SELECT sqlite_version()` from the running application. A Go module version is not the SQLite engine version. [Versioned driver documentation](https://pkg.go.dev/modernc.org/sqlite@v1.46.1) · [SQLite WAL reset bug](https://www.sqlite.org/wal.html#walresetbug)

Choose one SQL driver registration and one app-owned database policy. The old `glebarez/go-sqlite` wrapper and the `modernc.org/sqlite` top-level driver both register the name `sqlite`; importing both can collide. `session/database` itself imports GORM, not a mandatory SQLite driver, so `NewSessionServiceFromDB` allows a chosen compatible dialector and shared connection pool. A custom `session.Service` over the app database is another option if it passes ADK's conformance suite and preserves all event fields. Upgrading the underlying engine beneath an old wrapper needs integration testing; it is not evidence that the wrapper has been maintained. [Wrapper registration](https://github.com/glebarez/go-sqlite/blob/v1.21.2/sqlite.go) · [GORM dialector](https://github.com/glebarez/sqlite/blob/v1.11.0/sqlite.go)

Preserve ADK events intact and attach application records for run lifecycle, authorization, file changes, process receipts, and model timings. Publish committed records to the UI with a monotonic application sequence. Keep streaming deltas ephemeral or in bounded draft checkpoints; show interrupted output as a draft until a final event exists. `NodeInfo.Path`, `OutputFor`, `RequestedInput`, routes, and invocation/branch identity support graph attribution, but are not a complete public stream of every scheduler status transition. Instrument application node/tool wrappers and local telemetry for starts, failures, and cancellations; avoid inventing a completed state from elapsed time or the presence of text. [Event shape](https://github.com/google/adk-go/blob/v2.6.0/session/session.go) · [scheduler](https://github.com/google/adk-go/blob/v2.6.0/workflow/scheduler.go)

Implement durable local `artifact.Service` storage with versioned metadata and atomic file writes. The interface is available, but the inspected release tree supplies memory and GCS implementations, not the required local artifact library. Keep artifact revisions distinct from the live workspace files they came from. [Artifact contract](https://github.com/google/adk-go/blob/v2.6.0/artifact/service.go)

## Context, skills, and remote boundaries

Tail-retention compaction provides a rolling summary plus recent events; sliding-window summaries alone still grow over time. Compaction is lossy, so retain exact user constraints, workspace identity, and execution decisions in structured state, not only summaries. Tail-retention summaries append directly to session storage and bypass the normal plugin event pipeline. Therefore, secret filtering cannot rely solely on a plugin callback; enforce it at tool-result construction and storage boundaries. [Compaction contract](https://github.com/google/adk-go/blob/v2.6.0/session/compaction/compaction.go)

The Go skill toolset has metadata discovery, instruction loading, and resource loading. Its filesystem source expects immediate directories matching frontmatter names and lexically restricts resources to `references/`, `assets/`, and `scripts/`. The supplied `fs.FS` still determines symlink and filesystem behavior. Use a contained filesystem abstraction and size limits. Loading a script is not permission to execute it; all execution still goes through the tool broker. [Skill toolset](https://github.com/google/adk-go/blob/v2.6.0/tool/skilltoolset/toolset.go) · [filesystem source](https://github.com/google/adk-go/blob/v2.6.0/tool/skilltoolset/skill/filesystem_source.go)

A2A is optional interoperability with remote agents, not a prerequisite for cooperating local agents. Keep it outside the initial trusted execution core. The released remote v2 adapter checks origins of network-fetched agent-card interfaces, but local card targets are left to the caller. Any later A2A feature needs the same endpoint allowlisting, credential scoping, data-sharing decisions, and cancellation receipts as other network tools. [Remote adapter](https://github.com/google/adk-go/blob/v2.6.0/agent/remoteagent/v2/a2a_agent.go)

## Required integration experiments

1. Run a real Ollama/Gemma conversation with a read-only tool, then an authorized file edit and test command. Verify partial/final text, structured arguments, tool IDs, cancellation, error classification, usage, and model unload behavior.
2. Exercise static branches, parallel workers, unconditional joins, nested dynamic calls, and separate context branches. Reject conditional joins before execution. Demonstrate the global inference limit also covers dynamic work and summarizers.
3. Pause before a mutation, quit, reopen, approve once, submit the same approval again, and verify one authorized effect. Change the file and workflow between pause/resume and require explicit reconciliation.
4. Crash after an external effect but before its result is stored. Recover an unknown outcome without automatic duplicate execution. Test partial failure in one parallel branch while another has completed.
5. Run the upstream join-resume, timeout, and empty-loop cancellation regression shapes against each dependency candidate. Compare release and fix-containing pins before selecting one.
6. Run session-service conformance and migrations against local SQLite. Round-trip compaction-only events, node metadata, approval schemas, artifact references, and errors. Verify UI replay after dropped frontend subscriptions.
7. Force long context and tool output. Prove aggregate model-call, wall-time, output-byte, and nesting budgets; confirm secret filtering also covers compaction. Released `RunConfig` has no `MaxLLMCalls`; even main's added limit excludes some summarizer work and gives nested agent-tool runs separate budgets, so retain an application-wide ledger. [Released RunConfig](https://github.com/google/adk-go/blob/v2.6.0/agent/run_config.go) · [main budget implementation](https://github.com/google/adk-go/blob/219c13059ecf654b7318d5927a607779711943e0/agent/run_config.go)

The remaining questions are empirical: exact Ollama/ADK multimodal fidelity, the chosen dependency pin's recovery behavior, and measured SQLite/UI throughput. No live ADK/Ollama execution or application build was performed in this research lane.
