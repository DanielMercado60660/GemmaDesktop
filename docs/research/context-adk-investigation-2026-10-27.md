## Concrete findings

**Requested context, generated output, and summary capacity are separate budgets.** The app's 32,768 context request does not enlarge its ordinary 8,192-token output ceiling. Pinned MLX clamps positive `NumPredict` to architectural context remaining and counts all decoded tokens, including thinking, against it. Its requested `num_ctx` is not the qualified hard context boundary. A length stop at 8,192 is therefore not evidence of an 8K input window or an ignored 32K setting. [MLX preparation and decoding](https://github.com/ollama/ollama/blob/fce745fe5e4f0c7741ca46fc5484c9471c997d00/x/mlxrunner/pipeline.go#L27), [previous runtime qualification](thinking-runtime-followup-2026-10-27.md).

Qwen explicitly clamps output to estimated remaining context, honors explicit user ceilings, and conditionally escalates or continues truncated output. Its current default compression calculation uses an 85% proportional term plus an absolute summary reserve; at a 32,768 window its small-window fallback uses the proportional term. Gemini's legacy compression service uses a 50% default, retains recent context, and makes a second summary-verification request. Gemini's separate newer context-management mode defaults off in the inspected configuration. These thresholds assume their surrounding budgeting and provider behavior; copying a percentage or a large output allowance alone is not a compatibility fix. [Qwen output clamp](https://github.com/QwenLM/qwen-code/blob/746d00c4c92eb77a75540231748d7f3eb89587aa/packages/core/src/core/tokenLimits.ts#L63), [Qwen thresholds](https://github.com/QwenLM/qwen-code/blob/746d00c4c92eb77a75540231748d7f3eb89587aa/packages/core/src/services/chatCompressionService.ts#L193), [Gemini compression](https://github.com/google-gemini/gemini-cli/blob/8080ea70a54cda947b6c4f38293f195241e45968/packages/core/src/context/chatCompressionService.ts#L557), [Gemini mode default](https://github.com/google-gemini/gemini-cli/blob/8080ea70a54cda947b6c4f38293f195241e45968/packages/core/src/config/config.ts#L1211).

**The former summary configuration could shorten constraints before the model saw them.** It imposed 4,096 characters per rendered part, 32,768 characters for the transcript at a 32K context setting, 1,536 output tokens, a 45-second deadline, and a private four-summary call limit. ADK applies its per-part cap to user text and earlier summary text as well as tool traffic, and can shrink every part further to meet the whole-transcript budget. That behavior is independent of whether the complete ordinary prompt would fit the runtime. The labeled transcript is escaped for attribution; it is not raw wire history. [ADK rendering and shrinking](https://github.com/google/adk-go/blob/5226417e7591bb75d680047b01578e0fa6078f09/session/compaction/llm_summarizer.go#L297).

**Thinking Off does not diagnose an empty stop.** Pinned Ollama suppresses generated thought-channel text when thinking is disabled, and malformed tool-call bodies can be logged and discarded without an API parse error. An empty visible result cannot distinguish these cases. Google documents ghost thought channels and the large-model empty-thought prefill. The pinned renderer and its bundled reference Jinja both omit that empty prefill after a tool response, so this is not an app-only formatting divergence. Do not invent a control-token repair without a controlled parser/prompt trace. [Parser filtering](https://github.com/ollama/ollama/blob/fce745fe5e4f0c7741ca46fc5484c9471c997d00/model/parsers/gemma4.go#L115), [parse failure handling](https://github.com/ollama/ollama/blob/fce745fe5e4f0c7741ca46fc5484c9471c997d00/model/parsers/gemma4.go#L308), [renderer](https://github.com/ollama/ollama/blob/fce745fe5e4f0c7741ca46fc5484c9471c997d00/model/renderers/gemma4.go#L138), [reference template](https://github.com/ollama/ollama/blob/fce745fe5e4f0c7741ca46fc5484c9471c997d00/model/renderers/testdata/gemma4_31b_chat_template.jinja2#L380), [Google guidance](https://ai.google.dev/gemma/docs/capabilities/thinking).

**Ordinary tool-cycle mapping is aligned; arbitrary interleaving is not lossless.** The local adapter preserves separate thinking, call/result identifiers, contiguous tool responses, and literal file text. Its regression covers reasoning retained through a tool cycle. Qwen similarly extracts literal output/error strings instead of adding an unnecessary JSON-string layer. However, our accumulator groups all thinking, text, and calls rather than retaining arbitrary interleaving. Qwen now preserves reasoning/text segments. That is a representational limitation to test if observed, not an established explanation for the recorded failures. Gemini's provider-specific thought-signature handling is not interchangeable with Gemma's reasoning replay contract. [Qwen conversion](https://github.com/QwenLM/qwen-code/blob/746d00c4c92eb77a75540231748d7f3eb89587aa/packages/core/src/core/openaiContentGenerator/converter.ts#L674), [literal results](https://github.com/QwenLM/qwen-code/blob/746d00c4c92eb77a75540231748d7f3eb89587aa/packages/core/src/core/openaiContentGenerator/converter.ts#L880), [local tool-cycle regression](../../internal/engine/engine_test.go).

**Recovery policy changes observed success rates.** Gemini uses bounded invalid-stream retries and targeted empty/thinking-only nudges. Qwen additionally has output escalation/recovery but respects explicit output ceilings. It may accept a quiet post-tool `STOP` after exhausting retries; that completion rule would weaken Gemma Desktop's required answer/verification evidence and should not be transplanted. Any future retry must be generation-only, precede tool dispatch, preserve failed attempts, and share the existing call/deadline budget. No uncertain tool effect may be replayed. [Gemini retry nudges](https://github.com/google-gemini/gemini-cli/blob/8080ea70a54cda947b6c4f38293f195241e45968/packages/core/src/core/geminiChat.ts#L1051), [Qwen output recovery](https://github.com/QwenLM/qwen-code/blob/746d00c4c92eb77a75540231748d7f3eb89587aa/packages/core/src/core/llm-chat.ts#L5387), [Qwen quiet-completion rule](https://github.com/QwenLM/qwen-code/blob/746d00c4c92eb77a75540231748d7f3eb89587aa/packages/core/src/core/llm-chat.ts#L7582).

## Focused application change

[Compaction configuration](../../internal/engine/compaction.go) now disables both ADK text-shortening caps (`-1`). Full text values reach the existing labeled/escaped transcript renderer; this is not a promise of byte-identical message serialization or factual summary recall. The integration-owned [adapter](../../internal/engine/adapter.go) declines summary requests above `min(contextSize × 4, 400000)` rendered characters, preserving the original history instead of accepting a silently shortened input. At 32K the guard is 131,072 characters. This is a coarse resource guard, not a token estimate or guarantee that input plus output fits a context window; the inference client's independent byte cap still applies.

The summary output ceiling is `min(3072, max(256, contextSize / 4))`; its deadline is 120 seconds, still bounded by the caller's earlier deadline. The summary model inherits the run's step limit and shares the same model-call/output-byte budget, eliminating its separate four-call ceiling. Summary generation events are forwarded through the same observer. The existing 60% compaction threshold and eight-event retention are unchanged.

[Regression tests](../../internal/engine/compaction_test.go) exercise the actual ADK summarizer through a mocked local Ollama endpoint. A transcript larger than the old 32K-character bound retains the full user constraint and previous-summary marker beyond their former 4,096-character truncation points. Another test permits six summary requests after an already-spent ordinary-call slot, then rejects the next request at the shared run budget. Existing tests retain tool pairs, restore durable summaries, reject incomplete summaries, preserve raw history on failure, and cancel a summary stream. These fixtures establish input preservation and budget behavior; they do not establish improved real-model completion or recall.

The focused race-enabled command `go test -race ./internal/engine -run 'TestCompaction|TestIncompleteCompaction' -count=1 -timeout=45s` passes all six selected tests. The prior-summary fixture uses the materialized content representation produced by ADK's compaction application step, retaining both the summary action and the text supplied to the summarizer. No live model test was run for this change.

## Remaining accounting limit

Pinned ADK's counter uses the latest model event's `PromptTokenCount`, then estimates only events after that event. The generated reasoning/text/tool calls on that usage-bearing event itself are not added there. Long retained output can therefore be absent from the next-call compaction estimate. Before the first usage report, the fallback also excludes system/tool-declaration overhead. These are source-level limits; attribution to a particular historical failure requires its event/request trace. Qwen explicitly includes retained output and pending input in its accounting. [Pinned ADK counter](https://github.com/google/adk-go/blob/5226417e7591bb75d680047b01578e0fa6078f09/internal/compactioninternal/tail_retention.go#L236), [Qwen retained-output accounting](https://github.com/QwenLM/qwen-code/blob/746d00c4c92eb77a75540231748d7f3eb89587aa/packages/core/src/services/chatCompressionService.ts#L248).

The focused change does not repair that counter, change model/runtime versions, increase ordinary generation limits, or create a hard 32K enforcement guarantee. Reproduce the accounting case with a fixture before selecting a correction, and qualify summary fidelity and real-model behavior separately. Existing failed attempts remain failed.

Ollama0.40.11 continues to treat `num_ctx` as a soft/reporting value for MLX. ChatHandler disables truncation to it; the runner enforces the model architecture's limit (262144 for these captured models), with generated output separately bounded by `num_predict`. ## Experimental structured action transport

Ollama0.40.11 exposes a general response `Format` grammar, but its native tool declaration does not constrain each generated function argument using that grammar. Its OpenAI-compatible routes map into the same parser, so switching API shape would not address the observed malformed argument syntax. [Native request type](https://github.com/ollama/ollama/blob/675150d6ad2747df1e218ef59de9194bc4a7e538/api/types.go#L136-L183), [MLX response grammar](https://github.com/ollama/ollama/blob/675150d6ad2747df1e218ef59de9194bc4a7e538/mlxrunner/client.go#L159-L187).

An explicit agent setting `toolProtocol: structured_json` now enables a qualification experiment. Native remains the default. The adapter replaces native declarations with a response schema containing one branch per declared tool and one final-answer branch. Completed JSON proposals are validated and converted to ordinary ADK tool calls, which still use the host executor, approvals, schema validation, scope and budget enforcement. Malformed, mixed native/JSON, unknown, or truncated actions never dispatch. Raw JSON is buffered and counted against output limits rather than streamed as user-facing prose. Context summaries remain prose.

The protocol supports inline object-rooted schemas; unsupported references/dialects/schema keywords fail explicitly. Tool observations require an attributed, reversible representation because Gemma skips bare tool roles without native declarations and strips channel-like strings from assistant content. Initial thinking remains outside the response grammar. The experiment must be qualified against actual runtime behavior before use as a default.

The first actual-runtime transport check passed in 6.404 seconds: the read-only agent read a file containing a random code and an unpredictable next filename, read that second file, and correctly reported both codes. Neither code was present in the user prompt, both tool calls were observed, and file hashes remained unchanged. This qualifies the selected schema/tool-cycle behavior, not the realistic coding task. It used 26B, context65536, Thinking Off, temperature0 and output1024. [Live read evidence](../evidence/structured-json-read-live.json), [build](../evidence/structured-build-info.json).

The runtime logged an xgrammar warning that non-provably-disjoint `oneOf` branches fall back to `anyOf` grammar semantics. The generated outer branches have mutually exclusive action/name constants, but nested tool schemas may not. Host validation therefore remains authoritative and rejects any proposal failing the original schema before dispatch; the successful read test does not certify every grammar keyword. [Captured warning and scope](../evidence/structured-grammar-observation.json). Numeric arguments that are integral must fit ±(2^53−1), including decimal/exponent forms, because downstream ADK/tool JSON maps use float64.

The first structured coding recovery used the same existing session/candidate, Thinking Off, temperature1, 16K output and 64K context. It returned a syntactically valid final answer after 47.209 seconds claiming edits and a successful 15-test run, but its durable receipt contained **zero tool calls, changes or commands**. Candidate hashes/tests remained unchanged, and the harness rejected qualification. A completed model turn is therefore not task completion. [Immutable recovery result](../evidence/realistic-followup-20261027-144947-5657927b.json), [variant provenance](../evidence/structured-coding-variant-provenance.json).

A fresh unchanged fixture with the same structured/Thinking Off configuration also returned a final answer without tools, in 8.633 seconds. It mixed a completion claim with a future plan, made no changes, and failed qualification. Thus the no-action behavior is not established to depend on prior failed-turn history. ## Deterministic preservation of original user text

The ordinary-conversation engine now restores user text omitted by compaction from the retained raw session events, as chronological quoted user history before the unchanged native current request. It never parses generated summary claims to reconstruct authority. User-role function-response containers, assistant content, thoughts, generated compaction actions, and delegated/workflow scopes are excluded. Later user requests supersede older ones; turn-specific instructions remain associated with their earlier turn. Permissions still come from the host.

The hook reads a fresh session-service view before each model request because ADK's initial session handle is a snapshot, and callback contexts do not expose `Session()`. An invocation-local value supplies the service and session identity. The archive is request-only; it is not persisted as a fabricated user turn or included as an extra model call. Its 64 KiB rendered UTF-8 bound fails explicitly rather than silently truncating. This is a text resource bound, not an exact tokenizer/context-fit guarantee or restoration of previous image pixels. Missing/ambiguous original-user identity is treated as an error rather than guessed.

This also repairs old lossy snapshots when their original events remain available. It cannot reconstruct raw user text already absent from a legacy transcript. Regression evidence: **149 top-level backend tests /272 including subtests**, ten packages, race detector and actual sandbox fixtures enabled; four separate opt-in live tests skipped. Tests cover repeated identical user turns around compaction exclusions, nine active tool calls, unchanged current text/image input, original role provenance, archive bounds and observed usage.
